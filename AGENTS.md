# AGENTS.md

Инструкция для ИИ-агентов, работающих в этом репозитории. Человекочитаемое описание —
в [README.md](README.md), контракт — в [docs/SPEC.md](docs/SPEC.md), итоги — в [REPORT.md](REPORT.md).

## Что это

Платёжный мини-API с идемпотентностью (ДЗ №2, вариант C1). Go, только стандартная
библиотека, хранилище in-memory. Реализация лежит в `service/` (модуль `paymentapi`).

## Структура

```
service/              Go-сервис — ЕДИНСТВЕННОЕ место с кодом
  main.go             точка входа, читает PORT (по умолчанию 8080)
  handlers/           HTTP-слой: роутинг, валидация, конверт ошибок
  store/              in-memory хранилище, потокобезопасное, идемпотентность
  apperr/             типизированные ошибки → (HTTP-статус, code) из SPEC §4
  store_test.go, handlers/*_test.go  юнит- и конкурентные тесты
docs/SPEC.md          контракт v1.0 — источник истины, менять осознанно
conformance/          чёрно-ящичный набор на Python (stdlib), 27 проверок по HTTP
workflows/            повторяемая процедура сборки проекта агентами
reports/              сравнение реализаций, отчёт ломателя, замер, PDF
sessions/             журнал сессий с дословными промптами
```

## Сборка, запуск, тесты

Работай из `service/`. **Важно про окружение этой машины:**

- `go env CC` может указывать на кросс-компилятор MinGW — тогда cgo-сборки (`-race`, `vet`)
  падают. Сервис на чистой стандартной библиотеке, поэтому:
  - обычный запуск/тесты: `CGO_ENABLED=0 go run .` / `CGO_ENABLED=0 go test ./...`;
  - с детектором гонок нужен нативный компилятор: `CC=gcc go test -race ./...`.
- Встроенная песочница Bash блокирует чтение `/usr/include` дочерним gcc из go —
  go-команды запускай с отключённой песочницей.

```bash
cd service
CGO_ENABLED=0 go run .                 # сервер на :8080 (или $PORT)
CGO_ENABLED=0 go vet ./...
CC=gcc go test -race ./...             # или CGO_ENABLED=0 go test ./... без -race
```

Общий conformance (поднимает сервер сам, проверяет контракт по HTTP):

```bash
CGO_ENABLED=0 python3 conformance/conformance.py service   # из корня репозитория
```

**Definition of Done для изменений в сервисе:** `go vet` и `go test -race` зелёные,
conformance даёт 27/27, `GET /healthz` отвечает 200.

## Соглашения

- Только стандартная библиотека Go — не добавляй внешние веб-фреймворки/зависимости.
- Деньги — только целые минорные единицы (`amount_minor int64`), никаких float для сумм.
- Все ошибки идут единым конвертом SPEC §4; новый вид ошибки — добавляй sentinel в
  `apperr` и код в SPEC §4, а не хардкодь строку в хендлере.
- Меняешь поведение контракта — сначала правь `docs/SPEC.md`, потом код и conformance.
- Комментарии и идентификаторы — в тон существующему коду (английский в коде Go).

## Проверка и правки — через отдельного агента

Проект собран по [workflows/spec-parallel-build.md](workflows/spec-parallel-build.md):
спека → несколько независимых реализаций в git worktree → **агент-ломатель в отдельной
сессии (не автор кода)** → сведение. Для нетривиальных правок держись той же схемы:
проверяющий не должен быть автором изменения.

## PDF-отчёта

Собирается без pip/venv (их на машине нет), через системный Google Chrome:
`python3 reports/build_report.py REPORT.md reports/report.html`, затем печать HTML в PDF
headless-Chrome'ом (см. [REPORT.md](REPORT.md), раздел «Что не сработало / трение»).

## Секреты

В репозитории секретов нет и быть не должно. `.env`, `settings.json`, ключи — под
`.gitignore`. Хранилище in-memory, реальных платёжных данных нет.
