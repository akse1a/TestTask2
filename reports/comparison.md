# Сравнение трёх реализаций контракта

Три субагента независимо реализовали `docs/SPEC.md` в своих worktree/ветках.
Объективная проверка — общий чёрно-ящичный набор `conformance/conformance.py`
(25 проверок по HTTP, включая 64-поточный тест конкурентности), одинаковый для всех.

## Итог conformance

| Реализация | Ветка | Подход | conformance | `go test -race` | LOC (.go) |
|---|---|---|---|---|---|
| A | `impl-a` | один `sync.Mutex` + две map, check-then-insert | **25/25** | ok | 723 |
| B | `impl-b` | слои `store`/`handlers`/`apperr`, `RWMutex` + резервирование ключа | **25/25** | ok | 843 |
| C | `impl-c` | `sync.Map` + атомарный `LoadOrStore`, SHA-256 нормализованного тела | **25/25** | ok | 761 |

Все три **функционально корректны** и проходят одинаковый контракт, включая гонку
на идемпотентности (SPEC §5). Различие — в архитектуре и глубине валидации.

## Разбор

**A — самая простая.** Один глобальный лок на всё; невозможно получить частично
обновлённое состояние. Инъекция `now`/`newID` для тестов. Минус: под нагрузкой один лок
сериализует и чтения, и записи.

**B — выбрана как основная.** Три чистых слоя, единая таблица «статус ↔ код ошибки»
в `apperr`. Валидация тела самая строгая из трёх: `amount_minor` парсится через
`json.Number`, поэтому строка `"100"`, `1.5`, `true`, `null` — все дают `invalid_amount`,
а не молча проходят. Есть кап тела запроса (1 MiB, `io.LimitReader`). Роутинг явный:
корректно разделяет 404 (нет пути) и 405 (метод не тот). Идемпотентность — через per-key
mutex: конкурентные создатели одного ключа кооперируются, создаётся ровно один платёж.

**C — самая изящная по конкурентности.** Идемпотентность держится на одном атомарном
`sync.Map.LoadOrStore` без лока на горячем пути; проигравший гонку кандидат просто
отбрасывается и никогда не индексируется по id — сироты не наблюдаемы. Ключ-reuse
детектится по SHA-256 нормализованной пары. Тонкость: отмена мутирует общий `*Payment`
и требует отдельного лока (реализовано per-Payment мьютексом).

## Решение

**Мержим `impl-b` в `main`.** Причина: при равной корректности она наиболее пригодна
к сопровождению (слои, типизированные ошибки) и наиболее строга к входным данным —
именно то, что проверяет агент-ломатель. Наработки A (инъекция часов для тестов)
и C (lock-free hot path) зафиксированы здесь как альтернативы; ветки сохранены в истории.
