# Сессия 03 · Агент-ломатель (отдельная сессия)

Отдельный агент в отдельной сессии — **не автор кода**. Цель: не подтвердить работу,
а сломать сервис. Гонял против `service/` (main-реализация, impl-b).

## Промпт (дословно отправленный агенту)

```
Ты — независимый проверяющий (агент-ломатель). Ты НЕ писал этот код. Твоя задача не
подтвердить, что сервис работает, а СЛОМАТЬ его. Веди себя как человек, который очень
хочет, чтобы он упал.
Контракт — docs/SPEC.md, код — service/. Подними сервер сам (CGO_ENABLED=0 PORT=8091
go run . в service/), дождись healthz=200, в конце убей процесс.
Работай итерациями, МИНИМУМ 10 попыток: придумай сценарий → выполни → запиши точный
запрос/ответ/вердикт (баг/не баг/спорно). Обязательно попробуй: кривой/пустой/гигантский
JSON; amount 0/отриц/дробный/строкой/>int64/null/1e3/ведущие нули; currency регистр/длина/
юникод/пустая; Idempotency-Key отсутствует/пустой/>255/юникод/тот же с другим телом;
параллельные POST с одним ключом; гонки на cancel; кривые пути и методы; переходы статусов.
Результат — reports/breaker.md: все итерации + сводка по опасности. НЕ чини код, только отчёт.
Честность важнее эффектности.
```

## Что вернул агент

- **61 сценарий** (58 одиночных + 3 конкурентных по 100 потоков).
- **Реальных багов (нарушений SPEC): 0.** Ни critical/high/medium.
- **2 minor-несоответствия текста спеки:**
  1. длина `Idempotency-Key` мерялась в **байтах**, а SPEC §2.1 — «255 символов»;
  2. код `not_found` для неизвестного пути отсутствовал в фикс-списке SPEC §4.
- Спорные, но защитимые: строгое отвержение `1e3`/`1.0`/`100.00`; `GET /payments/x/cancel`
  → 405; `Content-Type` не проверяется.
- Сломать не удалось: ни паник, ни крэшей, ни OOM, ни переполнений int64, ни гонок.
  Гигантское тело режется лимитом 1 MiB, глубокая вложенность — лимитом глубины JSON.
  100 параллельных POST с одним ключом → ровно один платёж; 100 параллельных cancel →
  единое `canceled`. После всех враждебных запросов `healthz` = 200.

Полный отчёт — `reports/breaker.md`.
