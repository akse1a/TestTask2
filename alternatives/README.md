# alternatives/ — параллельные реализации контракта

Здесь лежат две **альтернативные** реализации того же контракта [../docs/SPEC.md](../docs/SPEC.md),
написанные независимыми субагентами параллельно с основной. Основная (`impl-b`,
слоистая) выбрана и живёт в [../service/](../service/); эти две сохранены как
свидетельство параллельной работы и как материал для сравнения.

| Каталог | Модель конкурентности | Раскладка |
|---|---|---|
| `impl-a/` | один `sync.Mutex` + map (простейшая корректность) | плоская, файлы в корне модуля |
| `impl-c/` | `sync.Map` + атомарный `LoadOrStore`, хеш нормализованного тела | плоская, файлы в корне модуля |

Каждый каталог — **отдельный Go-модуль** (свой `go.mod`). Собрать/прогнать:

```bash
cd alternatives/impl-a && CGO_ENABLED=0 go test ./...
cd alternatives/impl-c && CGO_ENABLED=0 go test ./...
```

Сравнение трёх реализаций — в [../reports/comparison.md](../reports/comparison.md).
Раньше это были ветки `impl-a`/`impl-c`; при переходе на одну ветку `main` их
история вплетена в `main` через merge-коммиты, а код перенесён сюда.
